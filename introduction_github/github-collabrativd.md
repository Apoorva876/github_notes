# GitHub is a Collaborative Platform

## Overview

Collaboration is at the core of everything GitHub does.

Repositories help organize projects and their files, while pull requests help track changes made to a project.

GitHub provides features such as **Issues** and **Discussions** to support collaboration.

---

# 1. Issues

**GitHub Issues** are used to track:

* Ideas
* Feedback
* Tasks
* Bugs

Issues can be created in different ways depending on the workflow.

### Ways to Create an Issue

An issue can be created from:

* An item in a task list
* A note in a project
* A comment in an issue or pull request
* A specific line of code
* A URL query

---

## Creating an Issue from a Repository

Follow these steps:

1. On **GitHub.com**, navigate to the main page of the repository.
2. Under the repository name, select **Issues**.
3. Select **New issue**.
4. If the repository uses issue templates, select the appropriate issue type.
5. If the required type is not available, select **Blank issue**.
6. If the repository uses issue forms, complete the structured form.
7. In the **Add a title** field, enter a title for the issue.
8. In the **Add a description** field, describe the issue.
9. If you are a project maintainer, you can:

   * Assign the issue to someone
   * Add it to a project board
   * Associate it with a milestone
   * Apply a label
10. Select **Submit new issue**.

### Issue Templates and Labels

**Labels, mentions, and reactions** can be used to manage collaboration effectively and increase issue visibility.

**Issue templates** help maintain consistent structure and expectations for contributors.

# 2. Discussions

Some conversations are more appropriate for **GitHub Discussions**.

Discussions can be used to:

* Ask and answer questions
* Share information
* Make announcements
* Discuss ideas
* Provide general feedback

Discussions are designed for conversations that are not necessarily tied directly to code. They provide an open, ongoing communication space within a shared forum.

---

# 3. Enabling Discussions

Repository owners and users with **Write access** can enable GitHub Discussions for public and private repositories.

The visibility of a discussion inherits the visibility of the repository where it is created.

### Steps to Enable Discussions

1. On **GitHub.com**, navigate to the main page of the repository.
2. Under the repository name, select **Settings**.
3. Scroll down to the **Features** section.
4. Under **Discussions**, select **Setup discussions**.
5. Under **Start a new discussion**, edit the template according to the community's tone and resources.
6. Select **Start discussion**.

You are now ready to create a new discussion.

---

# 4. Creating a New Discussion

Any authenticated user who can view the repository can create a discussion in that repository.

### Steps

1. Navigate to the main page of the repository or organization.
2. Select **Discussions**.
3. On the right side, select **New discussion**.
4. Select a discussion category by choosing **Get started**.
5. Enter a **Discussion title**.
6. Enter the discussion content under **Write**.
7. Select **Start discussion**.

> **Note:** Every discussion must be placed in a category. Repository maintainers define these categories.

---

# 5. Discussion Categories

Each discussion category has a unique name, emoji, and description.

Categories help maintainers organize conversations and distinguish between Q&A, announcements, ideas, and other types of discussions.

| Category             | Purpose                                                               | Format                |
| -------------------- | --------------------------------------------------------------------- | --------------------- |
| 📣 **Announcements** | Updates and news from project maintainers                             | Announcement          |
| #️⃣ **General**      | Anything and everything relevant to the project                       | Open-ended discussion |
| 💡 **Ideas**         | Ideas to change or improve the project                                | Open-ended discussion |
| 🗳️ **Polls**        | Polls with multiple options for the community to vote for and discuss | Polls                 |
| 🙏 **Q&A**           | Questions for the community to answer                                 | Question and Answer   |
| 🙌 **Show and Tell** | Creations, experiments, or tests relevant to the project              | Open-ended discussion |

---

# 6. Marking a Comment as an Answer

In a **Q&A-style discussion**, a comment can be marked as the accepted answer to the original question.

### Steps

1. Navigate to the discussion.
2. Locate the comment that best answers the original question.
3. Select **Mark as answer** below the comment.

The comment will be highlighted, making it easier for others to find the solution.

An answer can also be unmarked if needed.

---

# 7. Reference a Discussion in an Issue

If a discussion leads to work that needs to be tracked, the discussion can be converted into an issue.

### Steps

1. Navigate to the discussion.
2. Select the **`...`** (three dots) menu at the top-right of the discussion.
3. Select **Reference in new issue**.
4. Confirm the new issue title and body.

This helps keep track of actionable work that originates from community conversations.

---

# 8. Pinning a Discussion

Repository maintainers can pin important discussions to the top of the **Discussions** page for better visibility.

### Steps

1. Navigate to the discussion.
2. Select the **`...`** (three dots) menu at the top-right.
3. Select **Pin discussion**.

Pinned discussions can be useful for highlighting:

* Important announcements
* Important questions
* Ongoing topics
* Information the community should notice

---

# Issues vs Discussions

| Issues                                         | Discussions                                            |
| ---------------------------------------------- | ------------------------------------------------------ |
| Used to track ideas, feedback, tasks, and bugs | Used for conversations and community interaction       |
| Focuses on work that needs to be tracked       | Focuses on communication                               |
| Can be assigned to people                      | Used for questions, ideas, announcements, and feedback |
| Supports labels and milestones                 | Uses discussion categories                             |
| Can track actionable work                      | Can lead to an issue when work needs to be tracked     |

### Easy Way to Remember

> **Issue → Track the work**

> **Discussion → Discuss the topic**

---

# Key Takeaways

* GitHub supports collaboration through **Issues** and **Discussions**.
* **Issues** are used to track ideas, feedback, tasks, and bugs.
* **Discussions** are used for questions, ideas, announcements, and general feedback.
* Discussions must belong to a category.
* Q&A discussions can have an accepted answer.
* A discussion can be referenced in a new issue when it leads to actionable work.
* Important discussions can be pinned for better visibility.
* Labels, mentions, reactions, and issue templates help improve collaboration.
